LCLS-I timing stream
====================

The LCLS-I timing system sends a continuous stream of 16-bit symbols with two K
flags each. A fiducial starts a frame that carries a data buffer, the pulse id,
and a slot for every event code, and the rest of the time the link idles. This
page describes the stream as the regression's reference model encodes it,
:repo:`tests/common/timing_model.py`; the model's frames equal what
``TimingStreamTx`` transmits symbol for symbol in simulation, and
``TimingStreamRx`` decodes them. The diagrams are generated by running the
model's encoder.

Each symbol has a high byte lane (``data(15:8)``, K flag ``dataK(1)``) and a low
byte lane (``data(7:0)``, K flag ``dataK(0)``). The high lane carries the start and
end K characters and the data buffer bytes; the low lane carries the idle comma,
the pulse id bits, and the event codes.

Frame structure
---------------

Positions are counted from the start symbol:

.. list-table::
   :header-rows: 1
   :widths: 25 25 50

   * - Position
     - Symbol
     - Meaning
   * - 0
     - ``0x1C00`` ``10``
     - K28.0 on the high lane: start of the data buffer. The first symbol is
       ``0x1CBC`` ``11`` when the idle symbol before the fiducial was the other
       phase of the idle pattern.
   * - 2 + 2k
     - ``data << 8`` ``00``
     - Data buffer byte ``k`` for ``k`` from 0 to 51, least significant byte
       first.
   * - 105
     - ``0x3CBC`` ``11``
     - K28.1 and K28.5: end of the data buffer.
   * - 106 + 2j
     - ``0x0070`` or ``0x0071``
     - Pulse id bit ``j``, most significant bit first.
   * - 170
     - ``0x007D``
     - Event-code block marker.
   * - 172 + 2n
     - ``0x00nn``
     - Event code ``n`` when it is set; ``0x0000`` ``00`` when it is not.

Every odd slot between them is the comma ``0x00BC`` ``01``. The frame is 684
symbols, and the idle pattern alternates the comma with ``0x0000`` ``00``.

Behavior as measured
--------------------

These statements come from the simulation in
:repo:`tests/lcls2_core/test_TimingStream.py` and the model. Where the intent of
the maintainers is not confirmed they are marked observed, and the questions are
open as :issue:`211`.

- An unset event-code slot is ``0x0000`` ``00``, which is what ``TimingStreamTx``
  sends. ``TimingStreamRx`` reads every low-lane data symbol after the marker as
  an event code, so a slot that is not set reads as event code 0. Event code 0
  therefore cannot be sent as clear, and the receiver reports it as set in every
  frame (observed, intent unconfirmed).
- Event code 255 never reaches the wire (observed, intent unconfirmed).
- The receiver strobes no earlier than 14000 clocks after the marker. The prompt
  output carries the newest pulse id, event codes, and data buffer, and the user
  data buffer lags two frames except ``dmod(191 downto 160)``.
- An error cycle (``rxDecErr`` or ``rxDspErr``) after the marker clears the
  receiver for that frame, so the frame gives no strobe; the next clean frame
  decodes again.
